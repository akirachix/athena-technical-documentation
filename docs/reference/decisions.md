# Decisions

These are choices the team made, and why they matter.

| Decision | What it means |
| --- | --- |
| Requests and Negotiation were dropped | Buyers do not post requests, and there is no price negotiation. A buyer finds a listing and sends an enquiry |
| Collection happens outside the app | The two businesses arrange pickup and delivery themselves |
| Contact details show only after acceptance | A seller's details stay private until they accept the enquiry |
| Payment is by MTN Mobile Money | The buyer pays HUZA, and HUZA pays the seller out |
| Staff approve every business | A business cannot trade until it is approved |
| Staff accounts need an invite code | Only invited people can create a staff account |
| Three apps, one backend | The mobile app, the web app (PWA) and the admin dashboard all use the same API |
| No AI or sensors | HUZA does not use AI models or IoT devices |
| The approvals tab lives in the page address | The back arrow returns to the tab you came from |
